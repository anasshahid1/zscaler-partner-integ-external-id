# Zscaler Partner Integration — Shared External ID Onboarding Guide

## 1. What this does

Onboard one or many AWS accounts into Zscaler Partner Integration (Tag Discovery) using a **single External ID** that you control. This makes multi-account onboarding simple: one CloudFormation StackSet parameter set, one External ID, many accounts.

## 2. How it works

Normally Zscaler generates a different External ID for every AWS account. With this tool you supply one External ID and the tool:

1. Registers each AWS account in Zscaler with that External ID.
2. Deploys (or updates) the IAM role in each AWS account with the same External ID.
3. Forces Zscaler to re-check permissions and reports `Allowed` or `Denied`.

## 3. Prerequisites

- Python 3.9+
- AWS CLI v2 installed on the machine running the tool
- Zscaler OneAPI client credentials (Client ID, Client Secret, vanity domain, cloud)
- AWS credentials for each account you want to onboard — either an AWS CLI profile or an access key/secret/session token pair

## 4. Repository setup

Clone or download the repository:

```bash
git clone https://github.com/anasshahid1/zscaler-partner-integ-external-id.git
cd zscaler-partner-integ-external-id
```

No credentials are stored in the repository.

## 5. Zscaler credentials

Create a local CSV file (do not commit it):

```bash
cp cli/zscaler-creds.example.csv cli/zscaler.local.csv
```

Edit `cli/zscaler.local.csv`:

```csv
client_id,client_secret,vanity_domain,cloud,login_domain
your_client_id,your_client_secret,your_vanity,zscalerthree,zslogin.net
```

`cloud` defaults to `zscalerthree`. `login_domain` defaults to `zslogin.net`.

`cli/zscaler.local.csv` is gitignored and is never pushed to GitHub.

## 6. AWS account list

Choose one of the three methods below. For each account add one row to the CSV.

### Method A — AWS CLI profiles (recommended if profiles already exist)

```csv
account_name,aws_account_id,aws_profile,iam_role_name
prod-east,111111111111,prod-east-admin,ZscalerDiscoveryRole
prod-west,222222222222,prod-west-admin,ZscalerDiscoveryRole
```

### Method B — Access keys per account (no AWS profiles needed)

```csv
account_name,aws_account_id,aws_access_key_id,aws_secret_access_key,aws_session_token,iam_role_name
prod-east,111111111111,AKIA...,secret,,
prod-west,222222222222,ASIA...,secret,token,
```

- `aws_session_token` is only required for temporary (STS/SSO) credentials.
- Put this file in `examples/accounts.local.csv` or any `*.local.csv` path so it is gitignored.
- Keys are passed to the AWS CLI through environment variables for that subprocess only. They are never logged or committed.

### Method C — Zscaler side only, deploy AWS role separately

```csv
account_name,aws_account_id
prod-east,111111111111
prod-west,222222222222
```

Then deploy the role yourself with a CloudFormation StackSet:

- Template URL: `https://zscaler-discovery-role.s3.amazonaws.com/zscaler_discovery_role.yaml`
- `TrustingAccountRoleName` = `ZscalerDiscoveryRole`
- `ZscalerTrustedRole` = `arn:aws:iam::175726779870:role/ZscalerTagDiscoveryRole`
- `ExternalId` = the shared ID generated by the script

Re-run the script afterwards to verify.

## 7. Run

### Dry run (nothing created)

```bash
python3 cli/onboard_shared.py examples/accounts.local.csv --dry-run
```

### Real run

```bash
python3 cli/onboard_shared.py examples/accounts.local.csv
```

Output shows per-account Zscaler ID, AWS status, and `Allowed`/`Denied`.

## 8. External ID

The External ID is generated automatically on first run and saved to `~/.zscaler/shared-external-id`. Re-runs reuse it. You can override it with `--external-id <your-id>`.

## 9. Verification

The script calls `PUT /discoveryService/{id}/permissions` for each account. If an account shows `Allowed`, Zscaler can assume the IAM role. If `Denied`, wait a few seconds and re-run — IAM trust-policy changes can take a moment to propagate.

## 10. Cleanup

Delete a Zscaler registration:

```bash
python3 cli/zscaler_partner.py destroy --id <zscaler_id>
```

Delete an AWS CloudFormation stack:

```bash
aws cloudformation delete-stack --region us-east-1 --stack-name ZscalerTagDiscoveryTrustingRole-shared --profile <profile>
```

## 11. Security notes

- `175726779870` is Zscaler's public AWS account (trusted principal). It is the same for every customer.
- A shared External ID reduces confused-deputy protection compared with per-account IDs. Evaluate this for production.
- Never commit credential files (`*.local.csv`, `config.json`). They are gitignored in this repository.
